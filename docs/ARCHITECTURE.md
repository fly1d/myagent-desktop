# 架构与维护

```text
SwiftUI / AppKit 原生客户端
  │ 私有 stdin/stdout JSONL
  ▼
myagent-backend（本项目 Rust 程序）
  ├─ provider：模型地址、鉴权、HTTP、SSE 解析
  ├─ runner：有界工具循环、文件、命令与取消
  ├─ store：SQLite 迁移、线程、消息、轮次和事件
  └─ RPC：模型配置、客户端快照、执行状态
  │
  └─ 原生工具请求 → SwiftUI 授权/方案 → WKWebView / AX → 工具结果
```

后端不调用已安装的 Codex、Qoder 或其凭据。JSONL 协议使用线程、轮次和双向工具请求；模型调用与工具执行均有本项目自己的源码。

## 配置

`ProviderDraft` 只包含供应商、API 地址和模型。`SecureStore` 使用系统 Keychain Generic Password，按供应商和地址索引；更改地址不会自动取得旧服务的密钥。测试调用 `provider/test` 实际请求服务；明确保存后才写入钥匙串。

后端 `ProviderConfig` 在内存携带密钥；数据库只存公开配置。进程间使用父子管道，不监听局域网端口。`provider.rs` 负责地址与 TLS、HTTP 错误、流式文本和函数调用参数的解析，可增加其他协议适配器。

## 执行与恢复

`thread/start` 保存项目、指令和动态工具。`turn/start` 保存用户消息并启动后台模型任务，stdin 继续处理取消与工具答复。文本增量进入原生对话，函数调用进入后端工具或原生浏览器/桌面/方案工具。工具结果加入模型历史，继续迭代，直至完成、失败、取消或达到上限。

命令和文件变更通过单次原生审批。Shell 经你批准后以当前用户运行；路径限制不是操作系统沙箱。原生 `complete_task` 检查声明文件存在性并保存回执。客户端最多自动检查 0–3 轮；未验收显示“验收待确认”，可手动继续。

客户端缓冲 `turn/start` 返回前的事件，再按实际轮次 ID 路由，防止迟到的旧轮次请求借用新授权。停止使执行代次失效，取消本地工具、模型请求和后端执行。后端进程退出时取消活动任务。

SQLite 保存模型消息、轮次、事件和公开配置。原生任务列表和展示设置通过 `app/state/read/write` 保存，并保留 `state.json` 恢复快照；revision 防止旧状态覆盖新状态。密钥不进入这些快照。

执行任务与当前浏览任务的 ID 分开。一次运行一个任务，允许浏览其他任务，保留各自草稿。方案预览使用请求任务的项目目录。

## 原生工具

WKWebView 使用临时网站数据，独立于现有浏览器。来源、上传下载、表单导航和敏感字段有限制，截图来自真实渲染。普通按钮的自定义 JavaScript 仍可能产生网络副作用，授权来源不能替代具体操作判断。

AX 操作用户授权的应用和最近观察的元素，不激活应用、不注入全局键鼠。写入前等待用户空闲 3 秒，20 秒仍忙则取消。系统辅助功能许可与应用内短时授权分别检查。各应用支持程度不同。

## 维护

依赖固定在 `backend/Cargo.lock`。`./scripts/test.sh` 执行 Cargo 测试与 Swift 集成测试。本地模型 HTTP fixture 验证流式解析、工具往返和取消，不代替真实供应商回归。CI 测试后打包应用。

后续仍需完善真实供应商回归、长任务恢复、更多预览、供应商专有协议，以及发布签名和公证。多用户和云同步需单独的身份授权层，模型 API Key 不应当作产品用户身份。
